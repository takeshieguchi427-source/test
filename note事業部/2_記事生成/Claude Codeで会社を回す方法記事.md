# Claude CodeにAI社員5人を作って、note1本を最初から最後まで任せてみた話

# はじめに

最近、SNSやYouTubeで「AI社員を〇人作った」という投稿をよく見かけませんか。

「AI社員40人を作って、1ヶ月で全部やめた話」「10部門40人の仮想社員を雇った」。こういう投稿が、フォロワー数以上に読まれています。今回、こうした投稿や動画を実際に集めて調べてみたところ、伸びているものにはいくつかの共通点がありました。

この記事は、その調査結果と、実際に自分でAI社員の仕組みを作って動かしてみた経験をもとに書いています。Claude Codeというツールを使って、リサーチ・記事の執筆・タイトル決め・チェック・SNS宣伝という5つの仕事を、まるで5人の担当者がいるかのように分担させる方法を紹介します。

読み終えたときには、次のことができるようになっています。

- Claude Codeに「会社のルール」を教える`CLAUDE.md`というファイルが書けるようになる
- 自分の仕事を役割ごとに分けて、AI社員に振り分けられるようになる
- 1つの指示で、複数の工程を続けて動かせるようになる

専門知識は必要ありません。順番に読み進めてください。

---

# 第1章｜なぜ今「AI社員」という発想が伸びているのか

この章でわかること:YouTube・X(旧Twitter)・Web記事という3つの媒体を調べて見えてきた、伸びている投稿・動画の共通点がわかります。

## 擬人化して呼ぶと、伝わりやすくなる

今回調べたYouTube動画9本、Xポスト8件、Web記事12本のほぼすべてで、「自動化」ではなく「AI社員」「仮想社員」という言葉が使われていました。

たとえばXでもっとも反応が良かった投稿は、こはくさんという方の「AI社員40人を作って、1ヶ月で全部やめた話」でした。フォロワー33,200人に対していいねが2,900件つき、いいねの数をフォロワー数で割った比率は0.087倍。今回調べた8件のなかで最も高い数字でした。

2番目に反応が良かったのは、しょうへいさんの「Claude Codeで『10部門40人』の仮想社員を雇った」という投稿です。こちらは比率0.062倍でした。

簡単に言うと、「自動化しました」より「AI社員を雇いました」と言われたほうが、人は具体的にイメージしやすいということです。

## 「何人」という数字が、リアリティを生む

伸びている投稿には、もう1つ共通点がありました。「40人」「10部門」「8人部隊」というように、人数や組織の規模を具体的な数字で示している点です。

YouTube動画でもっとも再生数÷登録者数の比率が高かったのは、かいちのAI大学(Saixというコンサル会社が監修するチャンネル)の「Claude Codeで会社経営を行う方法とは？」という動画でした。登録者4.83万人に対して再生回数129,467回、比率は2.68倍です。この動画は個人の体験談ではなく、「知らないと損」という見出しと、200ページを超える特典資料の無料配布を組み合わせた作りでした。

2番目に比率が高かったのは、さきのAIでええやんさんの「ゼロからClaude Codeで自分専用のAIチームを作って仕事自動化する方法」で、比率1.42倍でした。こちらは関西弁を交えた個人の語り口が特徴です。

つまり、「体験談で個人の人柄を出す型」と、「見出しの強さと特典の量で押す型」の、2種類の伸び方があるということです。どちらも、読み手・視聴者に「自分にもできそう」「これは見ておいたほうがよさそう」と思わせる工夫が入っています。

## 失敗談のほうが、成功談より強いこともある

こはくさんの投稿が「作って、やめた」という失敗の話だったように、成功だけを語るより、うまくいかなかった経験を正直に話すほうが読まれる傾向も見えました。Web記事の調査でも、「理想と現実」というタイトルで課題を先に見せている記事が、実務的な深さがあるものとして評価されていました。

次の章から、実際にこの「AI社員」を、Claude Codeというツールでどう作っていくのかを説明します。

# 第2章｜CLAUDE.md ── AI社員に渡す「設計図」の書き方

この章でわかること:Claude Codeに毎回同じ説明をしなくて済むようにする、`CLAUDE.md`というファイルの書き方がわかります。

## 何度も同じ説明をしなくていい仕組み

Claude Codeに指示を出すとき、「丁寧語で書いて」「この言い回しは使わないで」といった注意を、毎回書き直すのは大変です。

そこで使うのが`CLAUDE.md`というファイルです。簡単に言うと、Claude Codeが作業を始めるたびに自動的に読み込んでくれる、ルールを書いたファイルのことです。一度書いておけば、次に指示を出すときにいちいち説明し直す必要がなくなります。

## 書く内容は、大きく4つ

CLAUDE.mdに書く内容は、次の4つに整理できます。

1. 誰が、誰に向けて発信するか(発信者名・ジャンル・読者像)
2. 話し方のルール(です・ます調にする、専門用語は噛み砕くなど)
3. 書いてはいけないこと(根拠のない数字を書かない、断定しすぎないなど)
4. 仕事の進め方(迷ったら質問する、成果物の保存先を決めておくなど)

たとえば、次のように書きます。

```markdown
## 誰が、誰に向けて書くか
- 発信者:HIKARI
- ジャンル:AIと副業
- 読者:これから副業を始めたい会社員

## 話し方・トーンのルール
- 文末はですます調。フレンドリーに
- 専門用語は「簡単に言うと〜」で噛み砕く

## 書いてはいけないこと
- 根拠のない数字を書かない
- 「必ず稼げる」「誰でも」などの断定は使わない
```

抽象的な精神論ではなく、こうした具体的な文章で書くほど、Claude Codeの動きはブレなくなります。

## 部署ごとにルールを分ける

会社全体の共通ルールに加えて、部署ごとに追加のルールを持たせることもできます。たとえば「品質チェック担当には、数字の根拠を特に厳しく確認させたい」という場合、品質チェック担当のフォルダに専用の`CLAUDE.md`を追加で置きます。

次の章では、この「部署ごとのフォルダ」を実際にどう作るかを説明します。

# 第3章｜役割で分ける ── フォルダ1つ＝AI社員1人

この章でわかること:1人のAIに全部任せるとうまくいかない理由と、役割ごとにフォルダを分ける作り方がわかります。

## 全部任せると、ルールが混ざってしまう

1人のAIにリサーチも執筆もチェックも全部任せると、リサーチのルールと執筆のルールが頭の中で混ざってしまい、どっちつかずの仕上がりになりやすくなります。逆に、1つの仕事に絞ったAIは、ルールがぶつからないぶん、精度が安定します。

## フォルダを役割ごとに作る

やり方はシンプルです。パソコンの中に、役割ごとのフォルダを作るだけです。

```
note事業部/
├── CLAUDE.md              ← 会社全体の共通ルール
├── 1_リサーチ/
│   └── CLAUDE.md          ← リサーチ担当専用ルール
├── 2_記事生成/
│   └── CLAUDE.md          ← 記事生成担当専用ルール
├── 3_タイトル/
├── 4_品質チェック/
└── 5_SNS集客/
```

フォルダの中でClaude Codeに作業を頼むと、会社全体のルールと、そのフォルダ専用のルールの両方を読み込んだうえで動いてくれます。

## 最初から完璧な組織を目指さない

いきなり5部署も6部署も作る必要はありません。まずは1つの役割だけ作って、実際に動かしてみることをおすすめします。動かしながら、必要になったところだけ増やしていけば十分です。

次の章では、この役割に「仕事のやり方」そのものを教える方法を説明します。

---

# 第4章｜スキルで「仕事のやり方」を教える

この章でわかること:一度教えたら、次からは一言で済むようになる「スキル」という仕組みの作り方がわかります。

## ルールと手順は別物

CLAUDE.mdが「いつも守るルール」だとすると、スキルは「1つの仕事の具体的なやり方」です。たとえば「リサーチのときは、YouTube・X・ネット検索の3つの経路から情報を集める」という手順そのものを、Claude Codeに覚えさせることができます。

## 手順を、そのまま文章で渡す

やり方は、普段Claude Codeに繰り返し出している長めの指示を、そのまま渡すだけです。次のように伝えます。

```
以下の手順を、リサーチ担当の「ネタ収集」スキルとして登録して。

# リサーチ担当:ネタ収集の手順
以下の3経路からネタを収集する。
1. YouTube:直近半年以内で、登録者が少ないのに
   再生が伸びている動画に絞る
2. X:フォロワーが少ないのに、いいねが伸びている
   投稿に絞る
3. ネット検索:複数の情報源を読み込んで、
   1本のレポートにまとめる
```

これを登録しておくと、次から「ネタ収集して」と一言頼むだけで、毎回同じ手順どおりに動いてくれます。

## 残りのスキルは、丁寧に書かなくていい

すべてのスキルを、最初から綺麗に整えて書く必要はありません。普段のやり取りをそのままコピーして「この流れをスキルにして」と頼むだけでも作れます。まずは動かしてみて、必要に応じて手直ししていくくらいの気持ちで十分です。

次の章では、この役割とスキルを組み合わせて、5つの工程を1つの指示でつなげる方法を説明します。

---

# 第5章｜5人をバトンリレーさせる ── 1行で全工程を回す

この章でわかること:リサーチから宣伝文の作成まで、5つの工程を1つの指示でつなげて動かす方法がわかります。

## 工程が変わるたびに頼み直すのは手間

役割とスキルができても、「リサーチ担当が終わったら、次は記事生成担当にお願いする」というように、工程が変わるたびに自分で指示を出し直すのは手間です。

そこで、5つの担当を順番に呼び出して、成果物を次の担当に受け渡すところまでを1つのスキルにまとめます。この記事では、そのスキルを「make-note」と呼んでいます。

## 全体の流れ

| 順番 | 担当 | やること | 成果物 |
|---|---|---|---|
| 1 | リサーチ | ネタを3つの経路から集める | リサーチ結果のファイル |
| 2 | 記事生成 | 目次→構成→本文の順で書く | 記事ファイル |
| 3 | タイトル | タイトル案を複数出す | タイトル案のファイル |
| 4 | 品質チェック | 言い過ぎ・矛盾・根拠のない数字を確認する | 検査結果のファイル |
| 5 | SNS集客 | 発売告知の投稿文を作る | 宣伝文のファイル |

このスキルを登録しておくと、「〇〇というテーマでnoteを作りたい」と1行伝えるだけで、5つの工程を順番に進めてくれます。

## それでも人が答える場面はある

完全に放っておいて終わる、というわけではありません。実際には、「自分の体験はどれを使いますか」「タイトルはどれにしますか」というように、途中で何度か質問されます。そこだけ自分で答えれば、あとはリサーチから宣伝文の作成まで、続けて進んでいきます。

次の章では、実際にこの仕組みを作って動かしてみた、今回の体験を紹介します。

# 第6章｜実際にやってみた話

この章でわかること:今回、この記事自体をAI社員の仕組みで作らせてみた過程で、何が起きたのかを紹介します。

## この記事は、AI社員に作らせた記事

ここまで説明してきた「役割ごとのフォルダ」「CLAUDE.md」「スキル」「5工程をつなげる仕組み」は、説明のための例え話ではありません。実際に自分のパソコンの中に作って、この記事自体を作らせるのに使いました。

まず、リサーチ担当・記事生成担当・タイトル担当・品質チェック担当・SNS集客担当という5つのフォルダを作り、それぞれにCLAUDE.mdを置きました。次に、リサーチ担当には「YouTube・X・ネット検索の3経路から情報を集める」という手順をスキルとして教え、最後に5つの担当を順番に呼び出す「make-note」というスキルを登録しました。

## つまずいたところも、正直に書く

うまくいかなかったこともありました。集めたリサーチ結果を保存するとき、ファイルの中身と名前がずれてしまい、「YouTube調査」という中身のファイルに、記事の分析結果を上書きしてしまったことがあります。あとから中身を読み直して間違いに気づき、正しいファイル名に戻しました。

もう1つは、YouTubeやXの再生数・いいね数を自動で取ってくることができなかった点です。ネットワークの制限で、動画サイトやSNSに直接アクセスできない環境だったため、結局はスクリーンショットを1枚ずつ確認しながら、数字を手作業で拾っていく形になりました。

## 任せる範囲を絞ったら、一気に楽になった

「全部自動でできる」と思っていた部分ほど、実際には人の確認が必要でした。一方で、「集まった情報を整理する」「共通点を表にまとめる」「文章の言い過ぎをチェックする」という作業は、完全に任せられました。自分ひとりでやっていたら、この記事を書き上げるまでにもっと時間がかかっていたはずです。

丸投げしすぎても、逆に細かく管理しすぎてもうまくいきません。ちょうどいい距離感を見つけるまでに、何度かのやり取りが必要でした。

# 第7章｜伸びる発信のコツ(リサーチから逆算)

この章でわかること:第1章のリサーチ結果を、自分の発信にどう活かせるかがわかります。

## 3つの媒体に共通していたこと

今回、YouTube・X・Web記事という3つの媒体を調べましたが、共通して見られた要素は次の3つでした。

1. 「AI社員」のように、擬人化した言葉で語る
2. 「何人」「何部門」という具体的な数字を添える
3. 成功談だけでなく、うまくいかなかった話も正直に書く

## 説明だけでも、伸びることはある

一方で、今回もっとも比率が高かったかいちのAI大学の動画のように、体験談ではなく端的な解説と、強い見出し・豊富な特典配布の組み合わせで伸びている例もありました。個人で発信する場合と、会社として発信する場合とでは、有効な型が変わってくる可能性があります。

## 自分の発信に落とし込む

もしあなたが、Claude Codeを使った経験を発信するなら、次のように考えてみてください。

- 「自動化しました」ではなく、「〇〇担当のAI社員を作りました」と言い換えられないか
- 何人分、何工程分の仕事を任せたか、具体的な数字で言えないか
- うまくいかなかったことを、1つでも正直に書けないか

この3つを意識するだけで、今回のリサーチで見えた「伸びる型」に近づけます。

# おわりに｜今日からできる最初の一歩

ここまで、リサーチの結果と、実際にAI社員の仕組みを作ってみた体験を紹介してきました。

大きな組織を最初から作る必要はありません。まずは1つの役割だけ作って、実際に動かしてみることが、何よりの近道です。

今日、これだけやってみてください。

CLAUDE.mdに、「誰が、誰に向けて発信するか」を1〜2行書いてみる。それだけで構いません。そこから、あなたの「AI社員」は動き始めます。
